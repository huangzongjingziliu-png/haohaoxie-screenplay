# 编剧助理 · 技能

对外只有一个概念：**技能**。审稿、写作都是技能，区别只在类型。内部代码沿用的历史标识（`expert`、`ExpertInfo` 等）不对外暴露，用户可见文案统一使用「技能」。

## 两种类型

| 类型 | 在界面里的位置 | 做什么 |
| --- | --- | --- |
| 审稿型 `review` | 助理面板 →「会审」 | 按方法论审阅当前场景或整稿，给出判断与修改建议 |
| 写作型 `writing` | 助理面板 → 写作技能下拉 | 在对话里做单步写作或改写，直接给出可用的文字 |

- 审稿型不进入写作下拉；写作型不参加会审（后端会拒绝）。
- 会审会先逐个执行审稿技能，再由「会审主持」汇总一次。

## 内置技能

内置审稿技能以方法论来源命名，让作者一眼看出这是谁的判断方法：

- 布莱克·斯奈德的节拍表
- 悉德·菲尔德的三幕结构
- 约翰·特鲁比的人物弧光
- 罗伯特·麦基的场景与冲突
- 罗伯特·麦基的对白与声口
- 竖屏短剧流派 · 短剧节奏

内置写作技能沿用原有的写作动作：续写、润色、扩写、对白优化。

内置技能不可改名、不可导出，但可以停用。

## 自定义技能

目录（新）：

```
~/Library/Application Support/ScreenplayStudio/skills/<id>/SKILL.md
```

旧目录继续读取，避免用户的旧文件失效：

```
~/Library/Application Support/ScreenplayStudio/experts/<id>/EXPERT.md
```

规则：

- 同一个 `<id>` 目录里优先读 `SKILL.md`，没有时回退到 `EXPERT.md`。
- 没写 `kind` 时按文件名推断：`SKILL.md` 视为写作型，`EXPERT.md` 视为审稿型。
- 新保存、导入的技能统一写成 `skills/<id>/SKILL.md`。
- 内置技能的 id 不可被覆盖；重复 id 会被跳过并在设置页列出原因。

### SKILL.md 格式

```markdown
---
id: my-skill
name: 我的审稿方法
description: 一句话说明这个技能看什么
kind: review
dimensions: [结构, 人物, 对白]
temperature: 0.4
max_tokens: 2400
---
这里写人格与方法论正文。审稿型要说明检查顺序和输出结构。
```

- `kind`：`review` 或 `writing`；写作型通常不需要 `dimensions`。
- `id` 只用小写字母、数字和连字符。
- 正文是模型看到的方法论提示词，不写操作说明。

### 管理入口

「设置 → 编剧助理 → 技能管理」可以：

- 启用 / 停用技能（状态存 `experts/.disabled.json`，不改技能文件）；
- 给自定义技能改名；
- 打开技能文件夹；
- 导入单个 `SKILL.md`（旧版 `EXPERT.md` 也可以）；
- 导出自定义技能为 Markdown 文件。

会审结束后点「存成我的技能」，可以把本次选中的审稿技能合成一个新技能，并选择保存为审稿型或写作型。

## 成本

会审默认串行：调用次数 = 选中技能数 + 1（汇总）。单个技能失败不影响其他技能；少于两个成功时不生成汇总。
