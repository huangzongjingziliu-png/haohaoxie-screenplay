# 0.1.59 更新说明

发布状态：本地构建，未发布。

## 新增：应用内 MCP 服务

外部 Agent 现在可以直接连接正在运行的好好写剧本，读写当前剧本，不再需要为 MCP 单独准备可执行文件。

- 打开方式：「更多 → 连接外部 Agent」。面板里显示本地地址与访问令牌，可分别复制。
- 地址：`http://127.0.0.1:8765/mcp`。端口被占用时自动顺延（如 8766），以面板显示为准。
- 鉴权：请求头 `Authorization: Bearer <面板里的令牌>`。令牌在首次启动时生成并保存在本机，重启后不变，客户端只需配置一次。
- 服务只在应用运行时可用，只听本机回环地址，不接受局域网访问。

客户端配置示例（Claude Code 一类的 Streamable HTTP 客户端）：

```json
{
  "mcpServers": {
    "screenplay": {
      "type": "http",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": { "Authorization": "Bearer <粘贴面板中的令牌>" }
    }
  }
}
```

### CLI 与老配置

- **CLI 仍然保留**：安装包内的 `screenplay` 命令、「安装终端命令」入口和原有用法都没有变化，已安装的用户不需要重装。
- **MCP 形态变了**：0.1.55 及更早的直售包里曾带一个 stdio 版 MCP 可执行文件，从 0.1.56 起已不再随包提供。如果你在更早版本里配置过指向应用包内的 stdio MCP，需要改成上面的 HTTP 配置。
- 使用 0.1.56–0.1.58 的用户此前没有 MCP 可用，这次是新增能力，无需迁移任何配置。

## 修复

- 通过外部工具（CLI / MCP）保存的项目，现在会出现在欢迎页「最近项目」里，重启后可直接打开。
- 退出应用时会清理桥接 socket，不再残留文件导致外部工具误判应用仍在运行。
- socket 改用系统临时目录短路径，避免路径过长导致的连接失败。
- 保存流程在目标目录无法创建临时文件时，改为直接写入目标文件；正常情况仍使用临时文件替换。商店（沙盒）版本保存到桌面、下载等用户目录不再失败。
- 商店渠道使用独立的钥匙串 service 名，避免与直售版凭据互相覆盖。

## 已知限制

- 当前发行验收只覆盖 Apple Silicon，Intel 未验证。
- MCP 服务提供当前项目内全部编辑工具，令牌等同本机读写权限，请勿分享。
- 商店版不提供 CLI 安装入口，也不随包携带 CLI。

## English

### New: in-app MCP server

Agents can now connect to the running app over a local Streamable HTTP endpoint and read or edit the current screenplay. Open More → Connect external agent to copy the URL and token from the panel.

- Endpoint: `http://127.0.0.1:8765/mcp`; the port moves to the next free one when occupied.
- Auth: `Authorization: Bearer <token>`. The token persists across launches, so a client only needs configuring once.
- The server runs only while the app is running and listens on loopback only.

The bundled `screenplay` CLI is unchanged. The stdio MCP binary that shipped with 0.1.55 and earlier is no longer packaged since 0.1.56; if you still have a stdio entry pointing into the app bundle, switch it to the HTTP configuration above. Users coming from 0.1.56–0.1.58 have nothing to migrate.

### Fixes

- Projects saved by external tools now appear in Recent and reopen after restart.
- The bridge socket is unlinked on quit, so external tools no longer see a stale socket.
- The socket moved to a short path in the system temp directory.
- Saving falls back to writing the target file directly when a temp file cannot be created in the destination folder.
- The store channel uses a separate keychain service name.

### Known limitations

- Only Apple Silicon is covered by release testing; Intel is unverified.
- The MCP token grants full local edit access to the current project; keep it private.
- The App Store build ships without the CLI.
